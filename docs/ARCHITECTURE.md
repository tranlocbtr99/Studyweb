# Studyweb architecture — accepted design (2026-10-24)
Frontend: React + TypeScript strict + Vite, Tailwind CSS, shadcn/ui, mobile-first, Cloudflare Pages static hosting.
Backend: Cloudflare Workers + Hono + Zod; D1 SQLite via Drizzle; R2 for private uploads when necessary; GitHub Actions for CI/CD; Vitest, Playwright, k6.
Monorepo paths: apps/web, apps/api, packages/db, packages/shared, tests/e2e, tests/load.
Two D1 bindings: exam_core (identity, catalog, immutable exam publications), exam_results (attempts, answer snapshots, submissions, grades, events). No cross-D1 transactions or foreign keys: exam_results stores immutable exam version ID plus content digest and necessary grading snapshot/reference; integrity across databases requires explicit application-level verification and a recoverable protocol. No assumption that splitting databases doubles account quotas.
Exam session: authenticate/start once; deliver questions without answer keys; render and answer locally; keep a local recovery draft; synchronize one attempt snapshot per ~60 seconds only when dirty, jittered per client; synchronize on page visibility changes when feasible (not guaranteed). Save responses are versioned with compare-and-swap, acknowledgment and bounded retries. Server timestamps control expiration. Final submit includes latest snapshot; server validates, grades, commits receipt and result durably within exam_results, then acknowledges. Repeated submit returns same receipt. Do not report success before commit.
Capacity target: 100–500 concurrent examinees, not yet validated. Illustrative 500 × (1 start + 60 saves + 1 submit + 1 result) = 31,500 API calls per 60-minute sitting, ~8.75/s average; spikes, retries, auth and admin excluded. Avoid synchronized writes; measure D1 queueing and Worker CPU. Plan free-tier budgets and alert at 70% of verified current limits; don't assume 0-cost or availability without testing.
Rollout phases: 1 foundation/security; 2 authoring/import/versioning; 3 exam/autosave/grading; 4 analytics; 5 performance/security/recovery testing and release. Prioritize database schema, API contracts and load models before detailed UI. No deployment yet.
