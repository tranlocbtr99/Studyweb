# Database schema implemented as initial migrations (not applied)
See packages/db/migrations/core/0001_initial.sql and packages/db/migrations/results/0001_initial.sql; Drizzle mappings in packages/db/src/.
exam_core: users, roles, user_roles, sessions, subjects, topics, questions, question_options, exams, exam_versions, exam_items.
exam_results: attempts (single JSON answer snapshot and save_version), attempt_events, scores, submission_receipts, audit_logs. Private grading_snapshot_json is stored per attempt, provisioned by trusted server code (not browser). Never send answer keys to students.
Within each database: foreign keys, indexes, unique constraints, JSON validity checks, published exam immutability triggers, score/receipt immutability. Across databases: no atomic transactions/FKs. App must validate user and immutable exam content digest when provisioning attempts.
Autosave CAS: UPDATE attempts SET answer_snapshot_json=?,save_version=save_version+1,updated_at=? WHERE id=? AND status='active' AND save_version=?; check affected rows. Finalization must commit attempt, score and receipt together within exam_results; idempotent retries return stored receipt. This application logic is NOT yet implemented.
Migrations are forward-only, independently applied per D1 after backup; tests written but not executed. Published version revocation is allowed only via status transition; historical snapshots never edited.
