# Database design (proposal, not migrated)
D1 SQLite via Drizzle. Candidate tables: users, sessions, questions, question_revisions, exams, exam_versions, exam_version_questions, attempts, attempt_answers, submission_receipts, grades, audit_events.
Use opaque IDs, foreign keys, explicit unique constraints and indexes. Published exam_versions and question snapshots are append-only; attempts reference an exact version. Keep answer keys in server-accessible tables only, separate from public question payloads.
attempts: user_id, exam_version_id, started_at, deadline_at (server-authoritative), status, save_version, submitted_at. attempt_answers: attempt_id + question_id unique, response JSON validated by question type, updated_at. Autosave requires expected save_version; conflict returns current server version for reconciliation. Submission uses atomic transaction/unique receipt keyed by attempt; repeated requests return identical grade/receipt. Enforce deadline and ownership on server.
Migration policy: forward-only additive changes, review SQL, backup/export and rollback plan before destructive changes; never reset production D1 or delete user data during upgrades. Exact schema deferred to database module.
