# D1 schema contract — design, no migrations applied
## exam_core
users(id PK, email UNIQUE, password_hash, status, created_at); roles(id PK, code UNIQUE); user_roles(user_id,role_id, UNIQUE pair); sessions(id PK, user_id FK, token_hash UNIQUE, expires_at, revoked_at); subjects(id PK, slug UNIQUE); topics(id PK, subject_id FK); questions(id PK, topic_id FK, status); question_options(id PK, question_id FK, stable_option_id, text, UNIQUE(question_id,stable_option_id)); exams(id PK, subject_id FK); exam_versions(id PK, exam_id FK, version_number, content_hash, published_at, status, UNIQUE(exam_id,version_number)); exam_items(id PK, exam_version_id FK, question_snapshot_json, answer_key_private_json, position, UNIQUE(exam_version_id,position)).
Published exam version and associated snapshots are immutable; no key leakage in student payload. Shuffle display order independently from stable option IDs.
## exam_results
attempts(id PK, user_id, exam_version_id, exam_content_hash, started_at, expires_at, status, save_version, answer_snapshot_json, updated_at, submitted_at, UNIQUE idempotent business constraints as appropriate); attempt_events(id PK, attempt_id FK, kind, payload_json, created_at); scores(id PK, attempt_id UNIQUE FK, points, max_points, graded_at, grading_version); audit_logs(id PK, actor_id, action, target_id, created_at). submission_receipts(attempt_id UNIQUE FK, idempotency_key, response_json, created_at, UNIQUE(attempt_id,idempotency_key)). Optional attempt_answers are materialized after submission, not rewritten for every autosave.
Cross-DB references (user_id, exam_version_id) cannot use SQLite foreign keys across databases; verify in application. Store a signed/verified immutable grading snapshot in exam_results at attempt creation, or establish a trusted immutable reference with failure handling; exact mechanism requires implementation review. Never trust browser-supplied answer keys. Keep any grading snapshot private.
Use D1 transaction/batch semantics only within the same database for final attempt status, score and receipt. Versioned CAS: UPDATE attempts SET answer_snapshot_json=?,save_version=save_version+1 WHERE id=? AND status='active' AND save_version=?; zero updated rows means conflict. Bound snapshot size; validate IDs, timestamps, ownership and payload shape. A successful save returns durable saveVersion; local draft is only fallback.
Indexes: attempts(user_id,started_at), attempts(status,expires_at), exam_items(exam_version_id,position), sessions(token_hash,expires_at), questions(topic_id,status); audit index by created_at. Add migration-reviewed constraints and test query plans.
Migration rules: separate forward-only Drizzle migrations per D1, backup/export and restore drill before risky changes; never drop historical attempts/results or mutate published versions. Database creation and SQL implementation are future tasks.
